# OpenFlux VPN: APK для Android

Неофициальный Android-клиент на основе
[p1neappleXpress/OpenFlux](https://github.com/p1neappleXpress/OpenFlux).
Версия `0.3-mtu`, пакет `local.openflux.client`, **ARM64, Android 8.0+**.

В приложении добавлен системный `VpnService` и TUN → SOCKS5. Настраивать прокси
в отдельных приложениях не требуется. В исходном OpenFlux нет готового проекта
Android APK: эта оболочка и мост TUN созданы отдельно.


## Установка и подключение

1. Установите `OpenFlux-local-arm64.apk`. Имя файла сохранено для обновления;
   название приложения на телефоне — **OpenFlux VPN**.
2. Выберите «Яндекс Документы» и проверьте ссылку. При обновлении сохраняется
   ранее введённый профиль; если там другой адрес, замените его ссылкой выше.
3. Оставьте **MTU 1200** и нажмите **«Подключить VPN»** и подтвердите системный запрос Android.
   На Android 13+ также запрашиваются уведомления.
4. Откройте сайт. В приложении доступны журнал и счётчики TCP/DNS.
5. **«Отключить»** в приложении или уведомлении останавливает TUN и ядро.

Root на телефоне не нужен. Android разрешает один активный VPN на профиль:
включение другого VPN отзывает разрешение у этого приложения.

Статус «VPN включён» означает создание системного VPN, а не успешную проверку
Интернета. При `config not found` / `editor_config nil` Яндекс не вернул нужную
конфигурацию редактора: проверьте, что это совместимый документ, используемый
выходной нодой, а не просто файл, изображение или страница предпросмотра.

## Что проходит через VPN

| Трафик | Поведение при включённом VPN |
| --- | --- |
| IPv4 / TCP всех приложений текущего профиля Android | Через TUN, OpenFlux и выходную ноду |
| Обычный DNS UDP/53 | Переводится в DNS TCP и передаётся через OpenFlux |
| DNS TCP, DoT и DoH поверх TCP/IPv4 | Через OpenFlux |
| Прочий UDP, включая QUIC, многие игры и звонки | Блокируется; приложения могут перейти на TCP, если умеют |
| IPv6 | Блокируется Android, поскольку ядро OpenFlux поддерживает только IPv4 |
| Собственные соединения клиента с Яндексом/MAX | Исключение для UID клиента, необходимое для доставки туннеля |

Системный DNS VPN: `10.77.0.2`, преобразуется в `1.1.1.1:53` с резервом
`9.9.9.9:53`. **Оба резолвера доступны только через OpenFlux**, прямого DNS
fallback нет. Явно заданный приложением IPv4-резолвер на порту 53 сохраняется.
Большие UDP-ответы DNS получают флаг TC, чтобы клиент повторил запрос по TCP.

Для полноценного UDP и IPv6 потребуется доработка **обоих** концов OpenFlux,
включая сервер. Одним APK это ограничение серверного ядра не снимается.

Маршрут `0.0.0.0/0` действует, пока существует TUN. Во время недоступности
транспорта трафик остаётся направленным в VPN. После ручного отключения,
завершения службы или отзыва VPN Android восстанавливает обычную сеть.
Always-on VPN и режим блокировки сети после завершения службы не реализованы.

## Полный набор команд для сборки на вашем Ubuntu / WSL

Сохраните `OpenFlux-APK.zip` в `/root/OpenFlux-APK.zip`. Архив содержит каталог
`OpenFlux-APK`; команды ниже распаковывают его в `/root/OpenFlux-APK`.

```bash
apt-get update
apt-get install -y git curl ca-certificates python3 unzip tar gzip openjdk-17-jdk-headless

cd /root
unzip OpenFlux-APK.zip
cd /root/OpenFlux-APK

export ANDROID_HOME=/root/Android/Sdk
export ANDROID_SDK_ROOT="$ANDROID_HOME"

bash build_apk.sh

ls -lh /root/OpenFlux-APK/dist/OpenFlux-local-arm64.apk
```

Регистр имеет значение: у вас каталог **`/root/Android/Sdk`**, с большой `S`.
Скрипт устанавливает только недостающие пакеты SDK:
`platforms;android-35`, `build-tools;35.0.0`, `ndk;27.0.12077973`.
При запросе лицензий ознакомьтесь с условиями и введите `y`, если принимаете их.
Нужен существующий Android SDK Command-line Tools / `sdkmanager`.

Go 1.26.4 используется из `/opt/openflux-go-1.26.4`, если установлен, либо
загружается с проверкой SHA-256 в `.tools` проекта. Android Studio и Gradle
для этой оболочки не требуются. Нужен Linux/WSL на x86_64 и доступ к GitHub,
Google Android SDK, go.dev и серверам модулей Go.

Открыть готовый APK в Проводнике из WSL:

```bash
cd /root/OpenFlux-APK/dist
explorer.exe .
```

Или установить на уже подключённый через ADB телефон:

```bash
/root/Android/Sdk/platform-tools/adb devices
/root/Android/Sdk/platform-tools/adb install -r /root/OpenFlux-APK/dist/OpenFlux-local-arm64.apk
```

Без ADB скопируйте APK на телефон, откройте файл и разрешите установку для
приложения, которым открываете его.

## Повторная сборка и подпись

Скрипт закрепляет исходное ядро на коммите
`a3be43bb514385c18f55f98e92dd7c02109d2118`. Встроенный SOCKS5-клиент дополнен
файлом `core-overlay/socks5.go`: полное чтение кадров протокола и передача
TCP half-close без потери ожидающего ответа. Исправление применяется к
**отдельной копии** исходников внутри `.work`, исходный каталог не меняется.
`core-overlay/apply.py` также заменяет фиксированный MTU 1500 в endpoint ядра
на значение `OPENFLUX_MTU`. Приложение передаёт туда MTU выбранного профиля;
по умолчанию 1200, допустимый диапазон 576–1500. Этот же MTU получают Android
VpnService и JNI-мост. Размер DNS-ответов учитывает выбранный MTU.

Можно использовать свою копию ядра:

```bash
cd /root/OpenFlux-APK
ANDROID_HOME=/root/Android/Sdk OPENFLUX_SRC=/root/OpenFlux bash build_apk.sh
```

Дополнительные переменные: `OPENFLUX_GO` — путь к Go 1.26.4,
`ANDROID_NDK_HOME` — путь к Linux NDK. Справка: `bash build_apk.sh --help`.

Подпись локальная. Ключ: `signing/openflux-local.jks`, alias `openflux-local`,
пароли хранилища и ключа — `android`. Если файла нет, скрипт создаёт новый ключ.
Сохраняйте его для обновлений. В архив исходников ключ не включён.
При сборке с новым ключом потребуется удалить ранее установленный APK;
сохранённый профиль тогда будет потерян. Подготовленная версия `0.3-mtu`
подписана тем же ключом, что и выданные ранее `0.1-local` и `0.2-vpn`.

## Структура

- `src/` — интерфейс, разрешение VPN, жизненный цикл службы и JNI-объявления.
- `native/bridge/` — gVisor IPv4/TCP, DNS UDP → TCP, SOCKS5, отмена и тесты.
- `native/cmd/jnibridge/` — Go/C JNI и реестр независимых сессий TUN.
- `core-overlay/` — поправки SOCKS5/MTU и регрессионные тесты самого ядра.
- `build_apk.sh` — Go/NDK → AAPT2 → Java → D8 → ZIP → zipalign → apksigner.
- `VALIDATION.md` — выполненные проверки и границы проверки.
- `third-party/` — тексты лицензий доступных зависимостей сборки.

`libopenflux.so` — отдельный PIE executable ядра, запускаемый через
`ProcessBuilder` из установленного `nativeLibraryDir`.
`libopenfluxtun.so` — JNI-библиотека TUN, загружаемая в процесс приложения.
Обе собираются под API 26 и ARM64 с выравниванием ELF на 16 КБ.
Дескриптор TUN дублируется в Go; Java и Go закрывают каждый свою копию.
При остановке отменяются сетевые операции, закрываются TUN и TCP-соединения,
завершается дочерний процесс. Служба наследует `VpnService.onBind` и обрабатывает
`onRevoke`; системная привязка защищена `BIND_VPN_SERVICE`.

MAX доступен как альтернативный транспорт. Укажите токен клиента и числовой
UID собеседника на ноде. Токен не сохраняется; URL, UID, порт и транспорт
сохраняются в закрытых настройках. Автоматическое резервное копирование выключено.
Журнал ограничен по размеру; введённые токен/ссылка скрываются, метаданные каждого
пакета не выводятся. Журнал может содержать адреса неудачных TCP-подключений.

## Проверка исходников моста

Для Linux с Go 1.26.4 и C-компилятором:

```bash
cd /root/OpenFlux-APK/native
/opt/openflux-go-1.26.4/bin/go test -race -ldflags=-checklinkname=0 -v -timeout 60s ./bridge
```

Если Go скачан скриптом, вместо `/opt/openflux-go-1.26.4/bin/go` используйте
`/root/OpenFlux-APK/.tools/go1.26.4/bin/go`. Тесты используют пакетный socketpair
и виртуальный TCP-стек: root, настоящее устройство TUN и доступ к Интернету
для самих сетевых проверок не нужны. Зависимости Go должны быть загружены.

## Ошибка сервера `Sendto failed: message too long`

Лог от 10.09.2026 показывает успешные небольшие TCP-пакеты и ошибки на
пакетах 1412–1472 байта. Это признак превышения допустимого MTU при отправке
raw IP с выходной ноды. В старом ядре OpenFlux у туннельного endpoint жёстко
задан MTU 1500. MTU Android сам по себе проблему не решает: встроенный SOCKS5
клиент принимает поток и создаёт новые TCP-пакеты собственным стеком.

В `0.3-mtu` выбранный MTU применяется на всех трёх уровнях. В регрессионном
тесте реального endpoint ядра при значении 1500 наблюдались пакеты до 1472
байт, а при значении 1200 — до 1172 байт, SYN MSS 1160. Передано и возвращено
384000 байт без потерь. Конкретный допустимый MTU вашей ноды не измерен;
1200 — консервативное стартовое значение, а не результат измерения маршрута.

1. Отключите VPN на телефоне и установите новый APK поверх предыдущего.
2. Оставьте MTU 1200, затем подключите VPN снова и повторно откройте сайт.
3. В журнале приложения должны появиться `MTU Android, TUN-моста и ядра OpenFlux: 1200`
   и `[TUNNEL] OpenFlux MTU=1200`.
4. Если остаётся `message too long`, пришлите новый фрагмент лога с длиной
   пакетов и результаты команд ниже. По ним можно подобрать значение точнее.

Команды выполняются **на выходной ноде**, в том же сетевом окружении, что и
OpenFlux (если он в контейнере — внутри контейнера):

```bash
ip -o link show
ip -4 route get 104.17.208.5
ip -4 route get 1.1.1.1
iptables -nvL OUTPUT --line-numbers
```

`operation not permitted` в присланном фрагменте относится к RST. Вероятная
причина — OUTPUT DROP для RST, рекомендованный самим OpenFlux. Linux Netfilter
может вернуть EPERM при DROP. Это гипотеза до просмотра правил; она не означает,
что серверу в целом не хватает CAP_NET_RAW, поскольку другие пакеты отправляются.
Правило не следует удалять вслепую: ядро Linux может иначе сбрасывать TCP-сеансы,
которые обслуживает пользовательский стек OpenFlux.

MTU интерфейсов, firewall и sysctl сервера этой сборкой не изменяются.
Отключать PMTU глобально для данного исправления не требуется; `IP_HDRINCL`
имеет дополнительные ограничения на размер пакетов.

Источники: [Linux raw(7)](https://man7.org/linux/man-pages/man7/raw.7.html),
[Netfilter: NF_DROP → EPERM](https://github.com/torvalds/linux/blob/master/net/netfilter/core.c),
[исходный OpenFlux](https://github.com/p1neappleXpress/OpenFlux).
